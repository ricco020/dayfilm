dayfilm

Film two seconds, a few times a day. In the evening, one command turns the folder into a single short film. dayfilm.sh is a 40-line shell script around ffmpeg that does exactly that with the clips already on your disk.

Use it

curl -O https://ricco020.github.io/dayfilm/dayfilm.sh
chmod +x dayfilm.sh
./dayfilm.sh ~/Videos/today film.mp4      # first 2 s of each clip
./dayfilm.sh ~/Videos/today film.mp4 3    # first 3 s instead

What it does

  • Reads every .mp4 .mov .m4v .3gp .webm file in the folder, oldest first, so the film follows the day.
  • Keeps the first two seconds of each clip.
  • Scales and centre-crops every clip to 1080 x 1920 portrait at 30 fps (change with W, H, FPS).
  • Gives a silent audio track to clips that have none, so the join never breaks.
  • Joins the parts without re-encoding a second time and writes one MP4.

Why the normalising step matters

The ffmpeg concat demuxer copies streams as they are. If one phone records 1080p at 30 fps and another 4K at 60 fps, or one clip has no sound, the joined file plays with frozen frames or drifting audio. Re-encoding every two-second part to the same size, frame rate, pixel format and audio layout first, then joining with -c copy, avoids that. It was tested on three clips of different sizes (640 x 360 at 25 fps without sound, 720 x 1280 at 30 fps, 1920 x 1080 at 60 fps with 48 kHz audio): the output is one 1080 x 1920, 30 fps file with a stereo 44.1 kHz track.

The same idea with friends

The script works for one person and one folder. Doing it as a group (everyone films at the same moments, the clips are gathered and the film is built for you) is what the app Klapday does: a closed group of friends each film two seconds a few times a day, and in the evening the app turns everyone's clips into one shared film. It is a separate product, free on Android and by invitation only inside each group. See klapday.com for how it works.
